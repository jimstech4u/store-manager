# What the shop can do, and what the screens let it do

Generated by reading the live database against every line of `src/`, then reading each result to
decide whether it is a gap or a design. Re-run the scan with:

```
python scripts/audit-ui.py
```

The scan is mechanical and over-reports. **This file is the reading of it**, which is the part
worth keeping: a helper called only from SQL is not a gap, and a table reached through an RPC is
not orphaned. What follows is what survived that reading, on 2026-08-30.

## Capability the database has and no screen reaches

Each of these is real, permissioned, and tested server-side. Nothing in the app calls it.

| What | Reached by | Why it matters |
|---|---|---|
| **Staff invitations** | `invite_staff`, `accept_invitations`, `store_invitations` | A shop can create staff logins but cannot invite anybody. The whole flow exists and has no door. |
| **Editing a staff member** | `update_staff_details` | Built alongside staff logins; a name or phone can be set once and never corrected. |
| **The activity feed** | `activity_feed`, `activity_feed_page`, `audit_log` | Every write is already logged. Nobody can read it — including the owner asking "who voided that sale?". |
| **Empties owed back** | `empties_outstanding` | A distributor's second ledger. The till records crates going out; nothing shows who still has them. |
| **Customer deposits** | `customer_deposits_held`, `deposit_ledger`, `deposit_forfeits` | Money held against returnables, with a forfeit path. No screen at all. |
| **Per-customer agreed prices** | `customer_prices`, `product_prices` | `resolve_price` already honours them on the till — a line quietly prices at "this customer's agreed price" and says so. Nothing can SET one. |
| **Product categories** | `product_categories` | `list_products` returns the name and the stock list shows it, but every form sends `p_category_id: null`. Read-only by accident: there is no RPC to list them either. |
| **Barcode lookup** | `product_by_barcode` | The form asks for a barcode and stores it. Nothing scans or looks one up. |
| **Searching sales** | `search_sales` | The sales list pages; it cannot be searched. |
| **Reopening a closed count** | `reopen_stock_period` | A count closed by mistake is final as far as the UI is concerned. |
| **Reviewing a variance** | `movement_reviews`, `variance_resolutions` | A count records a resolution; nothing lists them for review afterwards. |
| **Archive and restore** | `archive_customer`, `restore_customer`, `restore_product`, `restore_product_media` | Removing is wired; putting back is not. A mis-tap is permanent from the screen's point of view. |
| **Revoking a shared link** | `revoke_share_link`, `share_links` | A receipt link, once sent, cannot be withdrawn. |
| **Costing method** | `apply_weighted_average` | The shop is on FIFO layers. The switch exists and nobody can reach it. |
| **Joining a shop by code** | `find_store_by_code` | Presumably for staff onboarding; no screen. |
| **Price check** | `price_check` | A counter lookup — "what does this cost?" — with no screen. |

## Published with no consumer

Against the Library Charter's rule, and mine to fix:

- `selling_units_for_product(uuid)` — added this session for a per-product read the app never made;
  it uses the store-wide `product_selling_units` everywhere.
- `product_unit_gaps(uuid)` — same session, same problem. The form computes gaps client-side while
  typing (it must, to warn before Save) and the stock screen uses the store-wide
  `products_with_unit_gaps`. Either wire it to the product page or drop it.

## Stale in the app

- `src/components/ui/Collapsible.tsx` — nothing imports it. Quarantined to `_unused/`.
- Exports nothing else uses: `formatAmount`, `formatQtyWithPack`, `formatVariance`,
  `permissionsFor`, `isAllowedQty`, `canShareFiles`, `canShareLink`, `fetchReturnablesDue`,
  `draftSubtotal`, `lineBaseQty`, `fetchStoreMedia`, `isSupabaseConfigured`. Several are honest
  parts of a public surface (`isAllowedQty` states the rule the till enforces; `canShareLink` is
  half of a feature-detection pair) — the ones to look at are `formatQtyWithPack`, which describes
  the one-pack model that no longer exists, and `fetchReturnablesDue`, which is the empties screen
  that was never built.

## Not a gap

Recorded so the next scan does not re-raise them:

- Every `gtrgm_*`, `gin_*`, `word_similarity*`, `similarity*`, `set_limit`, `show_limit`,
  `show_trgm`, `strict_word_*` — `pg_trgm`, an extension, not ours.
- `is_store_member`, `has_permission`, `resolve_identity`, `normalize_phone`, `slugify_business`,
  `to_base_qty`, `generate_draft_code`, `refresh_period`, `unaccent_fallback` — helpers called from
  inside other functions, which is where they belong.
- `assert_product_units_settled`, `assert_sale_unit_allowed`, `unit_gaps_unchecked`,
  `sync_sale_units`, `dearest_live_cost`, `price_tier_coverage`, `stock_on_hand`,
  `stock_on_hand_bulk` — guards and derivations invoked by other SQL. Several are deliberately not
  granted to a browser.
- Tables named by no screen but reached through an RPC: `sale_lines`, `sale_charges`,
  `purchase_lines`, `purchases`, `payment_allocations`, `stock_layers`, `store_customers`,
  `identities`, `store_member_permissions`, and the rest of the write-side. Reading them through
  functions is the server-authoritative pattern, not an oversight.
